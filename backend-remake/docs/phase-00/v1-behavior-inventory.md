# V1 behavior inventory and migration classification

Audit date: 2026-08-13. V1 source is read-only under `backend`; remake source is under `backend-remake`.

## Audit method and totals

The inventory was rebuilt from `backend/src/server.js`, all `backend/src/router/*Router.js`, both socket files, both cron files, provider services/configuration and `frontend/src/services`.

- V1 structure: 23 models, 31 routers, 28 controllers, 34 services, 13 validations, 7 middleware, 2 cron jobs and 2 socket surfaces.
- Server registrations: 27 active base-path mounts and 3 commented/disabled base paths.
- Active HTTP surface: 138 method/path mounts after counting the six `classStudentRouter` routes under both `/api/class-student` and `/api/enrollment`.
- 76 active mounts have no `protect` middleware. This is an observed V1 risk, not a public contract for the remake.
- Disabled HTTP surface: 8 routes across Recording, webhook and VoIP.
- Source-only surface: 4 TeachingSchedule routes; `uploadUserRouter.js` is empty.

Legend: `P` = no V1 `protect`; `A` = V1 `protect` present. Body validation is only evidenced where the router invokes `validate(...)`; uploads use Multer without a complete authorization/limit contract. Exact response/status payload characterization is completed per module before a compatibility mapping is activated.

## Socket event contracts

| Surface                               | V1 behavior                                                                                                                                                            | Risk/gap                                                                                                         | Remake classification                                                                                                     |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Namespace `/chat` handshake           | JWT in `handshake.auth.token`; joins `user_{id}` and `admin_room` by token role                                                                                        | No session-revocation check; one in-memory socket per user; `user`/role semantics inconsistent                   | Preserve intent, change to shared session/participant policy and multi-tab presence                                       |
| Client `send_message`                 | `{ conversationId?, receiverId, content, messageType='text' }`; creates conversation/message then emits `receive_message`, `message_sent`, optional `new_user_message` | Supplied conversation/receiver is not proven to include actor; multi-write is non-transactional; payload logging | Preserve names only if consumer evidence requires; add validation, participation, idempotency and atomic/outbox semantics |
| Client `mark_as_read`                 | `{ messageId?, conversationId? }`; updates one/many and emits `message_read`                                                                                           | Does not prove message/conversation belongs to actor                                                             | Preserve intent; require participation/receiver policy and idempotent ack                                                 |
| Client `get_online_users`             | Admin receives `online_users`                                                                                                                                          | In-memory single-instance presence                                                                               | Preserve intent later with bounded multi-instance presence contract                                                       |
| Client `typing_start` / `typing_stop` | Emits `user_typing` to supplied receiver room                                                                                                                          | No participation validation; no ack/rate contract                                                                | Preserve intent later with participant check and throttling                                                               |
| Server connection/disconnect          | Emits `user_online`; errors use generic `error` event                                                                                                                  | No versioned ack/error schema; logging is inconsistent                                                           | Version event/ack/error envelope and reconnect ordering                                                                   |
| Default namespace discussion          | Requires token and arbitrary `handshake.auth.room`, then `socket.join(room)`                                                                                           | JWT is verified but room membership is not                                                                       | Intentionally change: derive/authorize room from resource membership; negative Socket E2E                                 |

No socket module is mounted in the remake during Phase 00.

## Job contracts

| V1 job               | Trigger/transition                                                       | Idempotency/concurrency evidence                                                                       | Remake classification                                                                        |
| -------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `initOnlineTestCron` | Every minute; `available=true` and `end < now` becomes `available=false` | Mongo update is repeatable but cron starts in every API process; no lease/owner/metrics                | Preserve business transition in Phase 07/12; move to durable scheduler with lock/idempotency |
| `submitTestSession`  | Every minute; delegates expired-session auto-submit                      | No scheduler lock, explicit idempotency key, timezone/late-submit contract or observed retry semantics | Preserve intended auto-submit only after assessment state machine/snapshot is frozen         |

Email, room provisioning and provider failure semantics are not durable jobs in V1; they must use outbox/retry/dead-letter status before later-phase release.

## Inventory limitations and next evidence

This is a source-grounded surface freeze, not proof that V1 behavior is correct. Per-module characterization must still record request fields, exact success/error statuses, response projection, side effects and frontend assertions before a compatibility mapping is enabled. Vulnerable/public behavior is explicitly excluded from parity even if a V1 test currently expects it.
